# Fluent v0.7.0

## Upgrade from v0.6.0

Update Fluent in your existing project. Preserve `.fluent`, managed candidate
workspaces, and saved configuration; do not rerun `fluent init`. Stop the old
shared scheduler before the new binary writes Work state, then run
`fluent status` with v0.7.0 and follow the exact public recovery command it
reports for your Work.

For an eligible Claude Writer that failed because its saved conversation is
missing, run the reported `fluent attempt run <work-item-id> <attempt-id>`.
Fluent verifies the unchanged candidate, saved assignment, retained zero-turn
failure, and settled execution before retrying that Writer in the same Attempt
with a fresh persistent conversation. It preserves the first commit, review
findings, and earlier execution evidence. Recovery still requires reviews, the
final Tester, required host acceptance, and successful Learning.

## Changes

- Repair the missing Claude conversation failure reported in
  [issue #4](https://github.com/mrinalwadhwa/fluent/issues/4). New Writers keep
  their conversations in the Attempt's private home and resume with the current
  assignment and findings. The recovery also recognizes the retained Claude
  result format with explicit null metadata, subject to the zero-turn checks.
- Admit the selected Node runtime and package tools for managed Writer and
  Tester execution, and grant the filesystem metadata reads needed to resolve
  declared worker inputs under confinement. Existing configuration and agent
  instructions remain available when upgrading unfinished Work.
- Preserve the Attempt's original target branch when the operator switches
  branches in the source checkout. Continued Writers and landing use that saved
  target, addressing [issue #5](https://github.com/mrinalwadhwa/fluent/issues/5).
- Improve native terminal attachment, SSH display and input handoffs, process
  settlement, and verification diagnostics accumulated since v0.6.0.
- Add read-only `fluent tester verify <work-item-id> <attempt-id> --candidate
  <full-commit>` to verify retained acceptance for the exact clean release
  checkout.

## Recovery limits

Missing-session recovery refuses changed evidence, active execution owners,
and failures with model or tool progress. Other pauses retain their existing
public recovery requirements; inspecting status does not authorize recovery.
Older binaries refuse mutations after new recovery authority is recorded.
Continue forward with the compatible binary: reinstalling an older executable
does not provide a supported rollback of newer Work state.

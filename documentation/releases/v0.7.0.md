# Fluent v0.7.0

In 0.6.0, a Claude Writer could make its first commit and then fail on the next
pass because Fluent could not find its conversation. A separate bug could leave
a reviewed, tested change unable to land after the project checkout changed
branches. Both failures are fixed in 0.7.0. This release also makes npm and npx
available inside Fluent's macOS sandbox.

## Upgrade an existing project

Stop the Fluent scheduler if it is running, then run `fluent update`. Confirm
that `fluent version` reports 0.7.0 and restart the scheduler if you use it.
Keep your project's `.fluent` directory and existing worktrees. You do not
need to run `fluent init` again. For unfinished work, run `fluent status` in
the project; it will show the next available action.

Once 0.7.0 has written to a Work Item, continue working on it with 0.7.0 or a
newer compatible version. An older binary will refuse to change that Work Item.

## Claude Writers keep their conversations

In [issue #4](https://github.com/mrinalwadhwa/fluent/issues/4), Claude
committed its first pass. When Fluent sent it back to address review feedback,
Claude exited immediately with `No conversation found with session ID`. Every
retry hit the same missing conversation. Fluent now saves the conversation in
the Attempt so the next writing pass can resume it.

For an Attempt already paused on this failure, run `fluent status`. If it
offers `fluent attempt run <work-item-id> <attempt-id>`, Fluent will start a
new Claude conversation with the saved assignment and review feedback. The
first commit and earlier evidence stay with the Attempt. This recovery is
available only when Claude did no work in the failed pass and the saved work
has not changed.

## npm, npx, and Work files inside the sandbox

The same report showed `node` working while `npx vitest` failed with
`Cannot find module '/usr/local/bin/npx'`. npm and npx were symlinks to files
outside the sandbox's allowed paths, so the Writer could not run the project's
tests. Fluent now gives Writers and Testers access to the selected Node
installation and its package tools.

The report also showed `Operation not permitted` when agents tried to read
the Work files that tell them what to build. Writers and reviewers can now
read those files from the project checkout.

## Landing stays tied to the Attempt's branch

In [issue #5](https://github.com/mrinalwadhwa/fluent/issues/5), the project
checkout changed branches while an Attempt was running. The change passed
review and 277 tests, but landing stopped with
`ordinary documentation review binding changed before landing`. Fluent now
records the Attempt's intended target branch and uses the reviews for its
final change. Switching branches in the project checkout no longer changes
where that Attempt lands.

## Native terminals and saved test results

The dashboard can now show live Codex, Claude, and Pi terminals, including
workers reached over SSH. You can watch a worker without taking over its input,
or take exclusive control when needed. If an SSH connection drops, reconnecting
returns to the same worker in watch mode. Input to a finished or canceled
worker is rejected.

`fluent tester verify <work-item-id> <attempt-id> --candidate <full-commit>`
checks a completed Attempt's saved test results and reviewed host evidence
against a clean checkout of that commit. It does not rerun tests or change
the Attempt.

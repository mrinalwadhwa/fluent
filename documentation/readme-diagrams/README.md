# Maintain the README diagrams

The SVG files in `sources/` are the authoritative README diagram sources. The files in `.github/assets/` are generated outputs that GitHub renders reliably. Edit the SVG sources instead of editing the PNG or GIF files directly.

Each diagram has a light and dark source. Keep both themes structurally identical: use the same words, geometry, and paths, and change only theme-specific colors. The renderer converts every source to a high-resolution PNG. It also adds flowing particles to the two `fluent-at-a-glance` sources and renders the animated hero GIFs.

## Render the assets

Install Python 3, `rsvg-convert` from librsvg, FFmpeg, gifsicle, and fontconfig. The SVG sources use Menlo explicitly because font fallback changes both layout and generated bytes. Menlo ships with macOS; use the documented rendering environment when it is unavailable rather than accepting another font.

On macOS with Homebrew:

```sh
brew install librsvg ffmpeg gifsicle fontconfig
```

Render all tracked outputs:

```sh
scripts/render-readme-diagrams.py
```

The renderer builds every output in a temporary directory before it updates `.github/assets/`, so a partial render does not leave a mixture of old and new assets. It keeps the diagram manifest and output sizes in the script rather than in a separate configuration file.

After rendering, inspect both themes at full size and at the width GitHub uses in the README. Watch the complete animated hero loop and check its final-to-first-frame transition. Then verify that the committed outputs match their sources:

```sh
scripts/render-readme-diagrams.py --check
```

`--check` renders into a temporary directory and compares every generated byte with the tracked assets. It reports missing tools, missing sources, missing outputs, and output drift rather than changing the repository.

The currently accepted assets were rendered on arm64 macOS 26.5.2 with Menlo, librsvg 2.61.3, Cairo 1.18.4, Pango 1.57.0, HarfBuzz 12.1.0, fontconfig 2.17.1, FFmpeg 8.0, and gifsicle 1.96. The renderer preserves FFmpeg's palette and frame rectangles instead of asking gifsicle to optimize or quantize them again. Both gifsicle 1.96 and 1.98 produce identical bytes with this setting; `gifdiff` confirmed that both themes retain the prior animations' displayed frames, timing, and loop behavior. This is a provenance snapshot, not a permanent version requirement; other versions may produce the same bytes. The byte comparison is the final check. When the output changes after a toolchain update, inspect both themes and the complete animation before updating the snapshot and accepting new assets.

Commit each source change with all of its regenerated outputs. The renderer produces these assets:

| Source pair | Generated output |
|---|---|
| `fluent-at-a-glance-{light,dark}.svg` | 2280×1686 PNG and 1200×888 animated GIF |
| `fluent-overall-flow-{light,dark}.svg` | 2040×1170 PNG |
| `how-you-tell-fluent-{light,dark}.svg` | 2040×1260 PNG |
| `how-fluent-builds-{light,dark}.svg` | 2040×1050 PNG |

## Change the animated flow

The hero animation uses the static hero SVG as its background. `FLOW_TRACKS` in `scripts/render-readme-diagrams.py` defines the particle paths in the SVG's 760×562 coordinate system. Update those tracks when a hero edit moves an arrow or changes the flow.

Each track completes a positive whole number of cycles during the 72-frame loop. Keep that invariant so particles return to their starting positions without jumping when the GIF repeats. Use animation to clarify the flow; keep labels, cards, and human-intervention arrows static.

Raster output can vary when rendering libraries change. When `--check` reports drift after a toolchain change, compare the images visually before accepting regenerated files. Do not update tracked outputs only to make the check pass.
